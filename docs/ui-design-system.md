# annot UI 设计系统 v1

## 适用范围

本规范同时约束：

- 本地工作台 `web/app.css`
- 独立动作图 `src/render.ts`
- 未来的插件、导出页和新增视图

它描述的是可验证的设计合同，不是视觉偏好清单。

## 什么是好的 UI

好的 UI 必须同时满足以下八项：

1. **信息正确**：显示内容来自真实数据，不把结构分、规范分冒充效果分。
2. **阅读优先**：用户先看到任务、对象和下一步，再看辅助信息。
3. **层级明确**：标题、正文、元数据、操作使用稳定的字阶与权重。
4. **空间有节奏**：相同关系使用相同间距，所有间距来自同一套 token。
5. **内容与边界分离**：文字不碰边框，卡片不贴卡片，标签不压线，箭头不穿文字。
6. **交互可识别**：悬停、焦点、选中、禁用和加载状态清晰，触控目标至少 44px。
7. **响应式有后果**：空间不足时重排或切换侧栏模式，不靠缩小字体硬塞。
8. **有证据**：每次改版必须有桌面与移动截图、几何检查和无重叠验证。

## 间距 token

工作台和动作图使用同一组语义：

| Token | 值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 图标与短标签 |
| `--space-2` | 8px | 紧凑控件内部 |
| `--space-3` | 12px | 组件内主要间隔 |
| `--space-4` | 16px | 卡片内边距、组件间距 |
| `--space-5` | 24px | 面板内边距、区域间距 |
| `--space-6` | 32px | 主区块分隔 |
| `--space-8` | 64px | 页面级留白 |
| `--gap-card` | 16–24px | 并列卡片间隔 |
| `--control-height` | 44px | 可点击控件最小高度 |

固定规则：

- 文本到卡片边界的最小距离为 16px。
- 并列卡片间隔不小于 16px；动作链摘要使用 24px。
- 标题到正文不小于 8px；正文到下一区块不小于 24px。
- 图谱列间距为 64px；连线只在列间通道垂直行进，不得沿卡片边框行进。
- 连线与卡片之间至少保留 14px。
- 缩放时连线使用 `vector-effect: non-scaling-stroke`，实时线宽保持 1.6–2px。
- 标签与阶段线、列标题线之间至少保留 12px。
- 页面移动端内边距为 16px，不得出现横向页面滚动。

## 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `--radius-small` | 6px | 标签、状态点 |
| `--radius-control` | 10px | 按钮、输入框、Tabs |
| `--radius-surface` | 16px | 面板、卡片、图谱节点 |

圆角用于表达容器边界，不用于所有装饰元素。

## 字体层级

| 角色 | 建议 |
|---|---|
| 页面标题 | 30–44px，1.05 行高，紧凑字距 |
| 区块标题 | 14–18px，1.3 行高 |
| 正文 | 12.5–14px，1.6 行高 |
| 元数据 | 10–11px，等宽字体或较低对比色 |
| 图节点标题 | 13px，最多三行，行高不低于 1.5 |

禁止用缩小字号解决空间不足。空间不足时优先换行、增宽、堆叠或切换布局。

## 布局合同

### 桌面三栏

- 左：Skill 库，桌面 304px；扫描范围、搜索和列表共用一个信息层级。
- 中：内容与动作图，弹性宽度。
- 右：卡片上下文与任务侧栏，`clamp(340px, 29vw, 420px)`。
- 右栏是网格的一部分，不覆盖中间内容。
- 收起右栏后，中栏自动占用释放出的空间。

### 响应式

- `>1120px`：三栏布局。
- `761–1120px`：左栏与中栏保留，右栏变为覆盖式侧栏。
- `≤760px`：单列内容，右栏全宽显示。
- 任何断点都不得产生页面级横向滚动。

## 组件合同

### Skill 库与扫描范围

- 「扫描目录」属于 Skill 库顶部，不再单独建立第二套列表标题。
- 默认工具根使用复选框，自定义路径使用逐行文本，二者由一个「应用并扫描」动作提交。
- 每个扫描项至少 40px 高，名称、路径、可用状态分三层显示；路径必须截断，不能撑破左栏。
- 扫描面板使用 `--radius-control`，内部项使用 7–10px 圆角，选中、悬停、不可读三种状态都要可辨认。
- 保存扫描配置只写 `.annot/web-roots.json`；任何 Skill 源文件写入仍留在宿主 Agent 对话中。

### Tabs

- 外层是包含 padding 的分段容器。
- 选中项必须有背景、边框和状态标签，不能只靠颜色或下划线。
- 相邻 Tab 至少保留 4px。
- Tab 最小触控高度 44px。

### 动作链与时序轨

- 标题区先给行动问题，例如「这个 Skill 按什么顺序执行？」，再给来源范围与点击结果；眉标使用 `SKILL ACTION FLOW`。
- 标题区右侧使用独立状态卡显示动作数量；内容区不足 480px 时状态卡移到标题下方。
- 时序轨每行至少 56px，编号圆点纵向由 1px 线串联，文本起于圆点右侧至少 12px。
- 编号必须可点击，并与右侧动作卡使用同一个节点 ID；点击后滚动到图表区、选中目标节点，并标记当前步骤。
- 时序轨采用分隔线和轻背景表达可交互行，不再使用一组厚重的大卡片。
- 摘要容器通过 `--overview-inset` 控制左右内缩：桌面 48px，窄栏至少 40px。
### 图谱节点

- 文字离卡片边缘至少 16px。
- 类型、标题、正文、来源 footer 使用稳定基线。
- footer 有分隔线，不与正文挤在一起。
- 连线不得穿过其他卡片；文字不得与连线共享空间。
- 跨列连线必须先进入列间通道，再沿通道转弯；禁止把长竖线画在卡片左边界或右边界上。
- 说明关联使用点线，执行关系使用实线；两条关系链不得共用一条无法辨认的路线。
- 缩放必须改变 SVG 的实际渲染尺寸，不能被响应式 max-width 覆盖。
- 重置缩放必须同时清空水平与垂直滚动位置。
- `annot verify` 同时检查动作摘要的保护间距：容器左右 ≥40px、标题内缩 ≥40px、说明与标题 ≥6px、标题带到动作卡 ≥20px、数量标签右内缩 ≥40px、动作卡左右内边距 ≥16px。

### 规范建议与评估任务

- 规范检查如果指出孤立说明，必须带“定位 N 条孤立说明”动作；点击后切到动作图、打开右侧卡片栏并筛选 `unbound`，不能只展示计数。
- 多选指标必须提供“全选/清空”单一开关，并随手动勾选状态同步；所有选项均可一次选中。
- 修改、分析、评估任务生成后必须自动打开大于右侧窄栏的原生 `dialog`。桌面宽度约 1080px、最高约 86vh；移动端保留 8px 外边距。
- 弹窗包含任务标题、生成边界、可滚动逐字任务文本、复制完整任务和关闭动作；Escape 与点击遮罩均可关闭。

## 强制验收

UI 改动至少执行：

```bash
npm test
node src/cli.ts verify <artifact.html>
node .agent/browser-qa.mjs <skill> http://127.0.0.1:8787
node .agent/graph-qa.mjs
node .agent/edge-audit.mjs <skill> http://127.0.0.1:8787
```

并在 1280、768、420、375 宽度检查：

- 页面无横向溢出。
- 面板收起与恢复正确。
- Tabs 三层状态清晰。
- 卡片、文字和连线无重叠。
- 连线不进入非端点卡片，也不贴卡片边框。
- 缩放可放大并能回到 100%。

## 为什么之前会反复出现 UI 问题

- Skill 提供了设计方法和审美原则，没有进入仓库成为可执行 token、组件规则和回归门槛。
- 图谱 CSS 在工作台的 `app.css` 与独立图的 `render.ts` 中分别维护，缺少共同规范。
- 过去主要依赖截图直觉逐处修补，没有固定的间距尺度，也没有几何回归。
- 缩放同时受 SVG 属性和响应式 CSS 控制，没有明确“谁是最终几何来源”。

本文件、双端 token 和 UI/浏览器验收共同解决这四个问题。
